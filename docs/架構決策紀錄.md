## ADR-001：加入「點到點巴士線查詢」（推翻原規劃書 §1.3「路線規劃不做」）

- **狀態**：已接納（Accepted）　日期：2026-10-12
- **相關里程碑**：M12
- **相關文件**：`docs/附近定位與點到點巴士線查詢計劃書.md` §1、§3

### 背景（Context）

原 `BusETA規劃書.md` §1.3 將「路線規劃（邊條路最快、轉車）」列為**明確不做**，理由係「需要圖路由／圖搜尋引擎，遠超本 app 範圍」。

經重新評估，發現該前提已經唔成立：

1. **資料已全量載入記憶體**：app 在 boot 時已將 KMB（6,752 站）+ CTB（2,587 站）全部路線站序載入 `DBS`，前端即時做「直達 + 一次轉車」BFS **零網絡成本**，唔需要任何後端圖路由引擎。
2. **跨公司合併已完成**（M9）：`XQ.group` / `routesOf` / `sequence` / `crossIndex` 令跨公司物理站天然聯合，跨公司轉車天然可行。
3. **高頻真實需求**：用戶實際場景「由 A 去 B 搭咩車」係常見查詢；直達 + 一次轉車已覆蓋絕大部分市區出行（例如觀塘→筲箕灣根本無直達，必定要轉）。

### 決定（Decision）

加入**點到點巴士線查詢**功能：

- **範圍**：只做**直達（0 轉）+ 一次轉車（1 轉）**。
- **唔做**：兩次或以上轉車、即時交通預測、步行導航路線、小巴／港鐵／渡輪、預估總時間（見 ADR-002 範圍配套決定）。
- **演算法**：`planTrip(originStops, destStops, { maxTransfers = 1 })` 放 `data.js`，純前端記憶體 BFS，深度 3；日後要加深只需改 `maxTransfers` 參數。
- **效能上限**：枚舉物理站 ≤ 2000 或計算 ≤ 200ms，超時只回直達並提示「路線較複雜，建議分段查」。
- **候選站展開**：起終點各展開 `WALK_RADIUS = 500` 米內候選上落車站。
- **排序**：轉車次數升序 → 總站數升序 → 總步行距離升序（步行距離 = 直線 ×1.3 路網因子，標「約」）。

### 後果（Consequences）

- **正面**：推翻咗一條已過時嘅「不做」決定，令 app 覆蓋最常用嘅點到點查詢場景，且無引入後端依賴。
- **風險**：
  - 步行距離係直線估算（×1.3），未必反映真實路網（緩解：標「約」+ 頁底免責）。
  - 多 `svc` 路線（如 40 svc1/2）直達／轉車判斷必須覆蓋全部 `svc`，唔只 `svc=1`（R-E）。
  - 轉車站方向單調性（`seq` 唔一定單調）須 `seq(上) < seq(轉) < seq(落)` 雙重校驗（R-G）。
  - 跨公司方向字母相反，須用 `XQ.routesOf` / `sequence`（已含 `normalizeDir`）（R-D）。
- **技術債**：演算法需新增 `[TRIP-*]` verify.mjs 群組（目標 +30 項）守住直達／一轉／跨公司命中與效能。

### 參考

- `docs/BusETA規劃書.md` §1.3（被推翻原文）
- `docs/附近定位與點到點巴士線查詢計劃書.md` §1、§3
- `public/js/data.js`：`B.findNearbyStops` / `B.stopRoutes` / `B.routeSeqs` / `XQ.*`

## ADR-002：一鍵定位附近巴士站（搜尋頁 GPS 掣 + nearby 重新定位）

- **狀態**：已接納（Accepted）　日期：2026-10-12
- **相關里程碑**：M11
- **相關文件**：`docs/附近定位與點到點巴士線查詢計劃書.md` §2

### 背景（Context）

規劃書 §1.2 關注「長者唔識授權 GPS」的可用性問題，因此 app 向來以**手動地標搜尋**為主入口，全站零 `navigator.geolocation` 呼叫。

但用戶實際出行常想「我而家喺度，附近有咩站」——呢個場景用手動搜尋要自己估自己喺邊個商場，體驗差。現有 nearby 頁（M3）已支援 100/200/500 米切換 + 兩家公司合併顯示，技術上已經可以接收一個 GPS 座標當 `place` 使用。

### 決定（Decision）

加入**一鍵定位**入口：

- **入口**：搜尋頁 `search-box` 下方加全寬大掣「📍 用我位置，搵附近巴士站」；成功 → 跳現有 nearby 頁，`state.place = { name:'目前位置', lat, lng, acc }`，**半徑預設 200 米**（用戶指定，唔改 range 預設語義）。
- **nearby 頁重定位**：`place-bar` 加「重新定位」掣（`nb-relocate`），唔使返回搜尋頁即可重跑 `getCurrentPosition` 並重設 `state.place` + 重畫地圖。
- **地圖藍點**：`openMap` 加 center marker 藍色 `divIcon` 標「我」＋半透明精度圈（半徑 = `acc` 米，clamp 50–500），與紅（九巴）／黃（城巴）pin 區分。
- **權限與失敗分類降級**：
  - `PERMISSION_DENIED(1)` → toast「未能取得定位，可用商場／大廈名搜尋附近站」；同一 session 唔再自動彈框。
  - `POSITION_UNAVAILABLE(2)` / `TIMEOUT(3)` → toast 建議稍後再試或手動搜尋，timeout 可 retry 一次。
  - 唔支援 geolocation → 隱藏掣 + tooltip「此瀏覽器唔支援定位」。
- **隱私鐵律**：GPS 座標**只喺本機**用 Haversine 算距離，**絕對唔傳任何第三方**（Nominatim 只收地標文字）；附近站計算純前端，零網絡請求。
- **Secure Context**：iOS Safari / Chrome 要求 HTTPS 先開到 `geolocation`；PWA 已部署 HTTPS，本地 `localhost` 測試 OK；部署 check 清單加一項「確認 serve 環境係 HTTPS」。

### 後果（Consequences）

- **正面**：完全復用現有 nearby 頁（100/200/500 切換、兩公司合併、地圖層），**零新 UI 結構成本**；同時為 M12 的「GPS 做起點」提供現成 `locateMe()` 邏輯，兩功能打通。
- **風險**：
  - GPS 唔支援／被拒機率高（R-A），必須有清晰降級與教育提示，退回手動搜尋——正正呼應 §1.2「長者唔識授權」初衷。
  - 半徑預設 200 米（顯示用途）與 M12 步行接駁半徑 `WALK_RADIUS=500` 米（規劃用途）邏輯不同，分開常數，唔可以混用。
  - HTTPS 要求（R-F）：部署須確認 serve 環境係 HTTPS，否則定位掣喺真機失效但本地測試 OK，容易漏測。
- **技術債**：需新增 `[GEO-*]` verify.mjs 群組（mock `navigator.geolocation`）守住成功／denied／unavailable／timeout／unsupported 五種路徑。

### 參考

- `docs/附近定位與點到點巴士線查詢計劃書.md` §2、§4（共用常數 `GEO_TIMEOUT=10000`）
- `public/js/app.js`：`openNearby` / `openMap` / `state.radius` 預設 200
