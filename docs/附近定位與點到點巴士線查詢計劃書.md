## 1. 背景與翻案

原 `BusETA規劃書.md` §1.3 將「路線規劃（邊條路最快、轉車）」列為**明確不做**，理由係「需要圖路由／圖搜尋引擎，遠超本 app 範圍」。本計劃書經評估後**推翻該決定**（見 ADR-001）：

- 本 app 已經在 boot 時將 KMB（6,752 站）+ CTB（2,587 站）全部路線站序載入記憶體（`DBS`），前端即時做「直達 + 一次轉車」BFS 零網絡成本，唔需要任何後端圖路由引擎。
- M9 已完成跨公司物理站合併（`XQ.group` / `routesOf` / `sequence` / `crossIndex`），令跨公司轉車天然可行。
- 用戶實際需求（「由 A 去 B 搭咩車」）係高頻場景，直達 + 一轉已覆蓋絕大部分市區出行。

## 2. 功能一：一鍵定位附近巴士站（M11）

### 2.1 行為規格

- **入口**：搜尋頁（`page-search`）`search-box` 下方加一行兩個大掣：
  - `📍 用我位置，搵附近巴士站`（全寬主掣）
  - `🧭 查點到點路線`（M12 入口，見 §3.3）
- **撳「📍 用我位置」流程**：
  1. 檢查 `'geolocation' in navigator`，唔支援則隱藏／disable 該掣並顯示 tooltip。
  2. `navigator.geolocation.getCurrentPosition(success, error, { enableHighAccuracy:true, timeout:10000, maximumAge:60000 })`。
  3. 成功：設 `state.place = { name:'目前位置', lat, lng, acc }`，`state.radius = 200`（**只喺此入口 override，唔改 range 預設 200 嘅語義**），`openNearby(place)` 跳去現有 nearby 頁。
  4. nearby 頁 `place-bar` 顯示「目前位置 ±acc 米」。
- **地圖藍點**：`openMap` 加 center marker 用藍色 `divIcon` 標「我」，與現有紅（九巴）／黃（城巴）pin 區分；`state.place.acc` 畫一個半透明精度圈（半徑 = acc 米，clamp 50–500）。
- **重新定位**：nearby 頁 `place-bar` 右側加「重新定位」掣（`nb-relocate`），重新跑 `getCurrentPosition` 並重設 `state.place` + `renderNearby()` + 重畫地圖，唔使返回搜尋頁。

### 2.2 權限與失敗降級（分類處理，唔可以一律「失敗」）

| `PositionError.code` | 含義 | 處理 |
|---|---|---|
| `1` PERMISSION_DENIED | 用戶拒絕 | toast「未能取得定位，可用商場／大廈名搜尋附近站」；同一 session 唔再自動彈框，改用掣手動觸發 |
| `2` POSITION_UNAVAILABLE | 訊號唔到 | toast「定位暫時唔到，請稍後再試或用手動搜尋」 |
| `3` TIMEOUT | 10 秒內無結果 | 同上；可 retry 一次 |
| 唔支援 geolocation | 舊瀏覽器 | 隱藏掣 + tooltip「此瀏覽器唔支援定位，請用手動搜尋」 |

- **Secure Context 要求**：iOS Safari / Chrome 要求 HTTPS 先開到 `geolocation`。PWA 已部署 HTTPS，本地 `localhost` 測試 OK；計劃書須註明，部署 check 清單加一項「確認 serve 環境係 HTTPS」。
- **隱私（同規劃書 §3.6）**：GPS 座標**只喺本機**用 Haversine 算距離，**絕對唔傳任何第三方**（Nominatim 只收地標文字）。附近站計算係純前端，零網絡請求。

### 2.3 檔案範圍（M11）

| 檔案 | 改動 |
|------|------|
| `public/index.html` | `search-box` 下加兩個大掣（定位／點到點）；nearby 頁 `place-bar` 加「重新定位」掣 |
| `public/js/app.js` | 新增 `locateMe()`、`relocateMe()`；`openNearby` 接受 `acc`；`nb-relocate` handler；`openMap` 藍點 + 精度圈分支 |
| `public/js/app.css` | GPS 掣樣式、藍點 `divIcon`、精度圈、重新定位掣 |

## 3. 功能二：點到點巴士線查詢（M12）

### 3.1 範圍（ADR-001）

- **做**：直達（0 轉）+ 一次轉車（1 轉）。
- **唔做**：兩次或以上轉車（候選爆炸、質素急跌）、即時交通預測、步行導航路線（只有直線距離）、小巴／港鐵／渡輪（資料只涵蓋 KMB+CTB）、**預估總時間**（見 §3.4 決策乙）。
- 演算法介面：`planTrip(originStops, destStops, { maxTransfers = 1 })`，日後要加深只需改參數。

### 3.2 演算法（核心，全前端、純記憶體）

**可用現成索引**（已驗證存在於 `data.js`）：
- `B.findNearbyStops(store, center, radius)` — 矩形預篩 + Haversine
- `B.stopRoutes(store, stopId)` — 某站所有 `(route, bound, svc, seq)`
- `B.routeSeqs[routeIdx]` — 某 (route,bound,svc) 站序
- `XQ.group(co, stopId)` — 跨公司物理站聯合（KMB↔CTB 同一站）
- `XQ.routesOf(co, stopId)` — 合併後該物理站全部路線（已處理 `normalizeDir` 方向字母相反）
- `XQ.sequence(co, route, dir, svc)` — 合併後沿線站序（含對面公司同物理站）

**輸入展開**：
- `origin` / `dest` 各為一個 `center`（GPS 座標或地標座標）。
- 展開成「`WALK_RADIUS=500` 米內所有候選上落車站」→ 再經 `XQ.group` 聯合成**物理站集合**（每端約 50 個物理站）。

**圖模型**：
- 節點 = 物理站（`co|stop` 經 cross 聯合，步行 0）。
- 邊 = 路線段：同一 `(route, bound, svc)` 站序中 seq 連續兩物理站之間可乘。

**`planTrip` 步驟**：
1. **直達（0 轉）**：對每對 `(o, d)` 物理站，查有冇共同 `(route, bound, svc)` 且 `seq(o) < seq(d)`。命中即一條直達方案（需覆蓋該路線全部 `svc`，唔只 `svc=1`，見 R-E）。
2. **一次轉車（1 轉）**：`o → routeA → transferStop → routeB → d`。
   - 枚舉 `o` 的每條路線（`XQ.routesOf`），取其 `sequence` 沿線可作轉車的物理站（經 `XQ.group` 聯合）。
   - 對每個 transfer 物理站，查佢有冇 `routeB` 令 `d` 在 `routeB` 後段（`seq(transfer) < seq(d)`，方向正確）。
   - transfer 可經 cross 配對（落 KMB 站、行 0 米轉 CTB 站上車）→ 天然支援跨公司轉車。
3. **效能上限**：BFS 深度 3，設 cap（總枚舉物理站 ≤ 2000 或計算 ≤ 200ms）；超過則**只回直達**並提示「路線較複雜，建議分段查」。
4. **去重**：同一走廊只留「站數最少」一條；跨公司同物理走廊合併。

**排序**（決策乙：只元數據，唔出總時間）：
1. 主：轉車次數升序（直達優先於一轉）
2. 次：總站數升序（少搭幾站）
3. 次：總步行距離升序（origin→上車站 + 落車站→dest）

**元數據欄位**（每方案）：轉車次數、每程路線號＋終點＋方向、各程站數、步行距離（直線 ×1.3 路網因子，標「約 X 米」）。**絕不顯示預估總分鐘**。

### 3.3 輸入方式（甲）

- **新頁 `page-trip`**：兩個搜尋欄 `起點` / `終點`。
- 每欄**復用現有 Nominatim 搜尋 + 候選點 + 多層快取**邏輯 → 抽出成 `searchPoint(inputEl, onPick)` 共用函式（現有搜尋頁邏輯重構，唔複製）。
- **起點欄額外「📍 用我位置」**：復用 §2.1 的 `locateMe()`，成功後 set `state.tripOrigin = 目前位置`。
- **站點跳轉**：ETA 頁（`page-eta`）／路線頁（`page-route`）加「查去處」掣 → `openTrip({ preset: { role:'origin'|'dest', co, stop } })` 帶入某站做起點或終點。
- 兩欄都 resolve 後自動 `planTrip()` 並渲染。

### 3.4 結果呈現（乙）

- **方案卡**（每卡）：
  - 標題：`直達` / `轉 1 次`
  - 路線段列表：每段 `[上車站名][路線號 badge＋終點＋方向箭頭][N 站][落車站名]`
  - 跨公司：段間標 `轉 九巴↔城巴`
  - 步行：`起點 → 上車站「步行約 X 米」`、`落車站 → 終點「步行約 X 米」`
  - 撳上車站 → `openEta(stop)`（**必須帶 `co`**，見跨公司 co 鐵律），需網絡查實時班次
  - **唔顯示總時間**
  - 頁底免責：`路線與步行距離為靜態資料估算（直線×1.3），實際以現場及實時班次為準`
- **空結果**：origin/dest 太遠無方案 → 提示「呢兩點可能需超過 1 次轉車，或適合搭其他交通工具（港鐵／小巴）」。

### 3.5 History／返回鍵整合（沿用 M10 慣例）

- `pageRenderable('page-trip')` → 返回 `!!state.trip`（origin+dest 已 set）。
- `restorePage('page-trip')` → 若 `state.trip` 存在則重跑 `planTrip()` 重繪（返回時唔使重新輸入）。
- `onPopState` 已處理地圖層；trip 頁開地圖時沿用現有 `openMap` 流程。
- 站點跳轉帶入 endpoint：`go('trip')` + `pushState`，與系統返回鍵同一 stack。

### 3.6 檔案範圍（M12）

| 檔案 | 改動 |
|------|------|
| `public/index.html` | 加 `page-trip` section（兩搜尋欄＋方案容器＋免責）；ETA／路線頁加「查去處」掣 |
| `public/js/data.js` | 新增 `planTrip()` 及 helpers（物理站聯合、路線段枚舉、直達／一轉搜尋），export 到 `window.BusETA` |
| `public/js/app.js` | `openTrip()`、`searchPoint()`（重構抽出）、「查去處」handler、`pageRenderable`/`restorePage` 補 trip 分支 |
| `public/js/app.css` | trip 頁佈局、方案卡、路線段視覺、跨公司標籤 |

## 6. 測試（verify.mjs 新增群組，目標 +30 項）

**演算法群組 `[TRIP-*`]**：
- 直達命中：選已知同線兩物理站 → 斷言回 1 條直達、轉車=0
- 直達否定：選已知不同線兩站 → 斷言無直達（或需轉車）
- 一次轉車命中：選已知需轉車對（如觀塘→筲箕灣）→ 斷言回 ≥1 條 1 轉
- 跨公司轉車：選需 KMB↔CTB 轉車對 → 斷言出現「轉 九巴↔城巴」
- 步行半徑邊界：origin/dest 刚好 500m 內有站 vs 外無站
- svc 多值：路線 40 多 svc 不漏判
- 方向 seq 順序：反向查詢（dest→origin）結果對稱
- 去重：同一走廊只留最少站數

**定位群組 `[GEO-*`]**（mock `navigator.geolocation`）：
- 成功 → 斷言 `state.place.name='目前位置'`、`state.radius=200`、`openNearby` 被叫
- denied / unavailable / timeout / unsupported → 斷言對應 toast、掣行為、唔跳頁

**整合群組 `[TRIP-UI-*`]**：
- `page-trip` 渲染、站點跳轉帶入 endpoint、History 返回重繪

## 8. 明確不做的事

| 不做 | 原因 |
|------|------|
| 兩次或以上轉車 | 候選爆炸、質素急跌，違背「輕鬆查到」定位（介面留 `maxTransfers` 可日後擴） |
| 即時交通／等車時間預測 | 無車輛實時位置、無班次表，預測必誤導 |
| 步行導航路線 | 只有直線距離，無路網路徑 |
| 小巴／港鐵／渡輪 | 資料只涵蓋 KMB + CTB |
| 預估總時間 | 決策乙：靜態估算易誤導，只顯示元數據＋免責 |
| 路線規劃後端／圖路由引擎 | 前端 BFS 已足夠覆蓋 0–1 轉，唔需要後端 |
