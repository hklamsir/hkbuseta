# 城巴／新巴 實時 ETA 資料可得性查證

> 查證日期：2026-10-07（HKT 20:1x）｜查證人：WorkBuddy（鵬城信息 AI 專家）
> 目的：確認 data.gov.hk 上的城巴（CTB）／新巴（NWFB）實時抵站時間（ETA）資料是否可得，並記錄整合 BusETA 所需的準確 endpoint 簽名與陷阱。

---

## 1. 結論

1. **城巴（CTB）實時 ETA 資料完全可得**：原生 API 提供 5 個 JSON endpoint，全部 live 探測返回 HTTP 200 並帶真實資料。
2. **2023 專營權合併 —— 新巴（NWFB）路線已併入城巴**：所有前新巴路線統一歸入 `company_id = "CTB"`。
   - `/route/nwfb` 雖返回 HTTP 200，但 `data` 為**空陣列** `[]`。
   - `/company/NWFB` 雖返回 HTTP 200，但 `data` 為**空物件** `{}`。
   - 即 NWFB 獨立代碼已停用，**唔存在獨立嘅新巴資料源**。整合時絕對唔好假設 NWFB 有獨立 API。
3. **數字政策辦公室（DPO）包裹 API 亦可用**：提供 `batch/stop-route` 與 `batch/stop-eta`，涵蓋**城巴（CTB）＋ 新大嶼山巴士（NLB）**，適合做「一站多線」快速查詢。

---

## 2. 資料集一：城巴的實時抵站時間及相關資料（原生 API）

- 資料集頁：`https://data.gov.hk/tc-data/dataset/ctb-eta-transport-realtime-eta`
- 提供機構：城巴有限公司（知識產權擁有人：城巴有限公司）
- 更新頻率：ETA 數據每分鐘更新；其他資料有改動時更新
- 語言：英文 / 繁中 / 簡中
- **Base URL：`https://rt.data.gov.hk/v1/transport/citybus-nwfb/`**

### 2.1 五個 endpoint（已逐一 live 實測）

| # | 資源 | Method + Path | 說明 | 實測結果 |
|---|------|--------------|------|----------|
| 1 | 公司 | `GET /company/{company_id}` | 公司基本資料 | `CTB` → 200 有資料；`NWFB` → 200 但 `data:{}` 空 |
| 2 | 路線 | `GET /route/{company_id}` 或 `/route/{company_id}/{route}` | 路線清單（可選指定路線） | `CTB` → 200，返路線陣列（含 orig/dest 中英文） |
| 3 | 巴士站 | `GET /stop/{stop_id}` | **只收 6 位 zero-padded stop ID** | `002737` → 200，返站名/經緯度 |
| 4 | 路線站序 | `GET /route-stop/{company_id}/{route}/{direction}` | direction = `inbound`/`outbound` | `CTB/1/inbound` → 200，返該方向站序陣列 |
| 5 | 預計抵站 | `GET /eta/{company_id}/{stop_id}/{route}` | 指定站指定線 ETA | `CTB/002403/1` → 200，返真 ETA（含 `eta` 時間戳） |

> 注意：`/route/{company_id}` 不帶路線時返全部路線；`/route/{company_id}/{route}` 只返單線。

### 2.2 ⚠️ 關鍵陷阱（與九巴 API 不同，整合必讀）

1. **Stop endpoint 簽名易錯**：係 `/stop/{stop_id}`，**只收 stop ID**，唔係 `/stop/{co}/{route}`。
   - 錯：`/stop/ctb/1` → 422 Invalid/Missing parameter(s)
   - 對：`/stop/002737` → 200
2. **Direction 格式有兩套，唔可以亂用**：
   - **Path 參數**用英文全字：`inbound` / `outbound`
   - **Data field `dir`** 用單字母：`I`（Inbound）/ `O`（Outbound）
   - 錯：`/route-stop/CTB/1/O` → 422 Invalid direction
   - 對：`/route-stop/CTB/1/inbound` → 200
3. **company_id 只得 `CTB` 一個有效值**（NWFB 已併入）。傳 `NWFB` 不報錯但返空。
4. **Stop ID 係 6 位左補零字串**（如 `"002737"`），唔可以傳數字 2737。
5. Response 中 `generated_timestamp `（v1.0）**字段名尾帶一個 trailing space**，解析時要小心（v2 才無空格；實測原生 API 仍返 v1.0 帶空格）。

## 3. 資料集二：城巴和新大嶼山巴士在個別巴士站的預計抵達時間（DPO 包裹 API）

- 資料集頁：`https://data.gov.hk/tc-data/dataset/hk-dpo-datagovhk1-transport-bus-route-list-and-eta-spcific-bus-stop`
- 提供機構：數字政策辦公室（DPO）｜來源：城巴 API + 新大嶼山巴士 API
- 本質：後台 batch 處理後，一次過返「某站經過嘅所有路線」或「某站所有 ETA」
- **Base URL：`https://rt.data.gov.hk`**

| # | Method + Path | 說明 | 實測結果 |
|---|--------------|------|----------|
| 1 | `GET /v1.1/transport/batch/stop-route/{company_id}/{stop_id}` | 某站經過的所有路線（含 dir/seq） | `CTB/001001` → 200 |
| 2 | `GET /v1/transport/batch/stop-eta/{company_id}/{stop_id}?lang=zh-hant` | 某站所有 ETA（跨線 batch） | `CTB/002403` → 200，返多線 ETA |

> 覆蓋範圍：CTB（含前新巴）+ NLB（新大嶼山巴士）。`company_id` 用 `nlb` 查新大嶼山巴士。

## 5. 對 BusETA 整合的建議

1. **可加 CTB adapter，NWFB 自動涵蓋**：目前 app 只得九巴 adapter，加城巴可補齊港島/過海線。因 NWFB 已併入 CTB，一個 `CTB` adapter 已覆蓋前兩間公司。
2. **資料模型可複用九巴**：核心欄位同構 —— `co` / `route` / `dir`(`I`/`O`) / `seq` / `stop` / `eta` / `dest_tc`。站序查詢 `route-stop` 已內含方向，無九巴 `svc` 那種「同一 (route,bound) 多 svc 站序不同」的複雜度（城巴無 svc 概念，路線→站序唯一）。
3. **Direction 映射**：城巴 path 用 `inbound`/`outbound`，data field 用 `I`/`O`。BusETA 內部若用 `I`/`O` 存方向，call API 時要轉換；`route-stop` 的 `dir` 直接係 `I`/`O`，可直用。
4. **一站多線快速查詢**：用 DPO 的 `batch/stop-eta/{co}/{stop_id}` 一次過取某站所有 ETA，類比九巴 `route-eta` 但更慳（見規劃書 §2 九巴 `route-eta` 13–43KB 的取捨）。但 DPO batch 係 `co` 分開查，要 CTB + NLB 兩次（NLB 非目標可省）。
5. **避免的坑**：
   - 唔好傳 `NWFB` 當 company_id（會靜默返空，難 debug）。
   - Stop ID 必須 6 位字串，前端/快取 key 要當 string 處理。
   - `generated_timestamp ` 尾空格：若用嚴格 JSON key 匹配要 trim。
6. **未來擴充**：NLB（新大嶼山巴士）同樣經此 API 可得（`company_id=nlb`），大嶼山線可日後一併加。

## 6. 與九巴 API 快速對比

| 維度 | 九巴（KMB） | 城巴（CTB） |
|------|------------|------------|
| 實時 ETA endpoint | `/eta/{stop}/{route}/{svc}` | `/eta/{co}/{stop_id}/{route}` |
| 路線→站序 | `/route-stop/{route}`（不帶 co） | `/route-stop/{co}/{route}/{direction}` |
| 方向表示 | `bound` 數字/字母 | path `inbound`/`outbound`；field `I`/`O` |
| svc 概念 | 有（同一線多 svc 站序不同） | 無 |
| 站 ID 格式 | 數字 stop ID | 6 位 zero-padded 字串 |
| 公司數量 | 1（KMB） | 1 有效（CTB，NWFB 已併入） |
| 回應大小（單站 ETA） | ≈ 1 KB | 類似（輕量） |

## 7. 實作期間補充查證（2026-10-09）

### 7.1 CORS 實測：可行，無需 proxy

在真實瀏覽器（經 Playwright + 本地 dev server）實測以下端點，全部 `fetch` 成功：

| 端點 | Host | 結果 |
|------|------|------|
| `/v1/transport/batch/stop-eta/CTB/{id}?lang=zh-hant` | `rt.data.gov.hk` | ✅ 200，dest/rmk 為中文 |
| `/v1/transport/citybus-nwfb/eta/CTB/{id}/{route}` | `rt.data.gov.hk` | ✅ 200 |
| `/v1/transport/citybus-nwfb/route/CTB` | `rt.data.gov.hk` | ✅ 200 |
| `/v1/transport/citybus-nwfb/route-stop/CTB/{r}/{direction}` | `rt.data.gov.hk` | ✅ 200 |

→ **跨域可直接讀取，app 毋須任何 proxy**。對比：Nominatim 需帶 Referer 且極短 UA 會 403（見規劃書 §3.4），但 data.gov.hk 對瀏覽器請求友善。

### 7.2 ⚠️ 方向 → 端點映射：查證報告與計劃書原先都寫錯了

本報告 §6 對比表只講「方向表示」差異（path 用 `inbound`/`outbound`、field 用 `I`/`O`），
**冇講清楚 `I`／`O` 各自對應哪個端點**。實測後確認（route 1，7 條路線抽樣）：

```
/route/CTB → orig_tc = 中環 (港澳碼頭)、dest_tc = 跑馬地 (上)

dir = 'O'（outbound，URL: /outbound）
  首站 001027 = 中環 (港澳碼頭)  → 末站 002403 = 跑馬地 (上) = dest_tc
  DPO batch ETA 對 dir='O' 亦回 dest = 跑馬地(上)   ← 與 dest_tc 一致

dir = 'I'（inbound，URL: /inbound）
  首站 002403 = 跑馬地 (上)  → 末站 001027 = 中環 (港澳碼頭) = orig_tc
```

**結論：`O` → `dest_tc`；`I` → `orig_tc`。**

語意解釋：香港巴士慣例中，`I`（inbound）係「往總站／市區方向」，`O`（outbound）係「開往終點」。
`/route/CTB` 的 `orig_tc` 對應 inbound 的終點、`dest_tc` 對應 outbound 的終點，
與 `app.js` 顯示用語（`I` = 「往總站方向」、`O` = 「開往終點」）完全對得上。

> **呢個係原 CTB-adapter 計劃書 §3.1 寫錯嘅地方**（原寫 `I → dest_tc`、`O → orig_tc`）。
> 若照計畫書實作，每條路線的**入站終點都會顯示錯**。已修正並由 [CTB-7] 測試鎖定。

### 7.3 CTB `/stop/{id}` 的坑（補充）

- `data` 係**物件**（`{co, stop, name_tc, lat, long, ...}`），**唔係陣列** → 通用 fetch 印「N 筆」時要用 `Array.isArray()` 判斷。
- 冇 bulk 端點（九巴有 `/stop` 一次過返全部）→ build 腳本必須先經 `route-stop` 枚舉所有 stop ID，再逐站抓（約 2,600 個請求，實測 6 分鐘）。
- 停車場／分站編碼（如 `(WT916)`）同樣存在，`groupKey()` 剝除邏輯兩邊通用。

### 7.4 路線數與站數實測（2026-10-09）

```
/route/CTB                    → 407 條路線
/route-stop/CTB/*/inbound+outbound → 17,404 筆站序、2,587 個獨立車站
```
